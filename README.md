# 태그스타 도감

포켓몬 태그스타 비공식 팬사이트. 태그 도감과 중고 시세, 트레이드 손익 계산기, 내 주변 설치 매장 지도를 제공합니다.

> 비공식 팬사이트입니다. 포켓몬 및 포켓몬 태그스타의 권리는 각 권리자에게 있습니다.
> 시세는 중고 거래 매물을 모아 추정한 참고값이며 실제 거래가를 보장하지 않습니다.

## 시작하기

```bash
npm install
npm run scrape   # 공식 사이트·시세 수집 → public/data/*.json, public/tags/*.png
npm run dev      # http://localhost:3000
```

`public/data` 가 비어 있어도 화면은 뜨지만 내용이 없습니다. 처음 받았다면 `npm run scrape` 를 먼저 돌리세요.

| 명령 | 설명 |
|---|---|
| `npm run scrape` | 전체 수집 |
| `npm run scrape -- --no-prices` | 시세를 건너뛰고 태그·매장만 (직전 시세를 재사용) |
| `npm run scrape -- --no-images` | 이미지 내려받기를 건너뜀 (직전 로컬 경로를 이어붙임) |
| `npm test` | 파서·시세 필터·점수·트레이드 판정 테스트 |

## 구조

```
scripts/scrape.ts      수집 오케스트레이터 (네트워크·파일쓰기·안전장치)
src/lib/
  parse-official.ts    공식 사이트 HTML 파서
  parse-prices.ts      중고 매물 필터와 중앙값
  rarity.ts            등급 체계, 표본 하한, 가치 상한
  scoring.ts           거래점수(TP) 확정
  trade.ts             트레이드 판정·사다리 경고·추가 추천
  geo.ts               거리 계산
public/data/*.json     화면이 읽는 데이터 (그대로 공개 API 로도 쓰인다)
```

`public/data/*.json` 은 `https://<도메인>/data/tags.json` 처럼 그대로 노출됩니다.
나중에 네이티브 앱을 붙일 때 서버를 새로 만들지 않고 이 URL을 그대로 쓰면 됩니다.

## 데이터

매일 06:00 KST 에 GitHub Actions 가 공식 사이트와 중고 시세를 다시 수집해 커밋합니다.

수집이 실패해도 기존 데이터는 그대로 둡니다. 수집 결과가 0건이거나 직전 대비 20% 이상 줄면
파서가 깨진 것으로 보고 쓰기를 거부합니다. 이 장치가 없으면 공식 사이트 개편 하루 만에
도감이 통째로 빈 화면이 됩니다.

### 거래점수(TP)

가치가 비선형이라 원화를 그대로 더하면 거짓말이 됩니다. ★4 이하는 사실상 0이고
★6 안에서도 편차가 몇 배로 벌어지기 때문입니다.

- 실거래 표본이 등급별 하한을 넘으면 중앙값을 TP 로 환산 (400원 ≈ 1TP)
- 넘지 못하면 `등급 기본값 × 인기 가중치` 로 추정하고 화면에 "추정치" 표시
- 어느 쪽이든 등급별 상한을 넘지 못하도록 자릅니다 — 표본 세 개짜리 ★3이 ★5보다
  비싸게 평가되는 것을 막기 위한 장치입니다

### 등급 사다리

합계 TP 가 같아도 ★6은 ★5 뭉치로 바뀌지 않습니다. 계산기는 이런 조합을 따로 경고합니다.
수량으로 메울 수 없는 구간을 알려주는 것이 이 계산기의 존재 이유입니다.

## 방문 통계

Firebase(Google Analytics 4)로 방문자를 측정합니다. 웹에서 Firebase Analytics 는 GA4 속성에
그대로 쌓이므로, 지표는 Firebase 콘솔과 GA4 콘솔 어느 쪽에서도 같은 것을 봅니다.
네이티브 앱을 붙일 때 같은 프로젝트에 앱 스트림만 더하면 웹과 앱을 한 속성에서 봅니다.

```
src/instrumentation-client.ts   앱 코드보다 먼저 실행돼 firebase 를 띄우고 전송 경로를 꽂는다
src/lib/analytics.ts            화면이 부르는 얇은 층 (버퍼 · 이벤트 정의 · 중복 방지)
src/components/TrackTagView.tsx 정적 상세 페이지에서 열람을 찍기 위한 클라이언트 경계
```

### 켜는 순서

1. Firebase 콘솔에서 프로젝트를 만들고 **Google Analytics 를 사용**으로 켭니다. 이걸 켜야
   측정 ID(`G-...`)가 생깁니다.
2. 웹 앱을 등록하고 SDK 설정값 중 네 개를 Vercel 프로젝트 환경변수에 넣습니다 (`.env.example` 참고).
   `NEXT_PUBLIC_` 값은 빌드 때 번들에 박히므로, 넣은 뒤 재배포해야 적용됩니다.
3. GA4 → 데이터 스트림 → **향상된 측정**이 켜져 있는지 확인합니다. 페이지뷰는 이 설정이
   브라우저 히스토리 변경까지 잡아 주는 데 의존합니다. 코드에서 페이지뷰를 따로 찍지 않는
   이유가 이것입니다 — 둘 다 하면 이중 집계가 됩니다.
4. Google Search Console 에 도메인을 등록하고 `sitemap.xml` 을 제출합니다. 검색 유입 키워드는
   GA4 가 보여주지 않습니다. SEO 로 사람이 들어오는 사이트라 사실상 여기가 본편입니다.

### 남기는 이벤트

| 이벤트 | 언제 | 파라미터 |
|---|---|---|
| `tag_view` | 태그 상세 페이지 열람 | `tag_no`, `rarity` |
| `trade_calculate` | 트레이드 양쪽이 채워져 판정이 나올 때 | `mine_count`, `theirs_count`, `verdict` |
| `map_locate` | 내 주변 찾기 버튼의 위치 권한 결과 | `result` (`ready`/`denied`/`unsupported`) |

트레이드는 태그를 담을 때마다 다시 계산되므로, 구성이 실제로 바뀐 순간에만 한 번 보냅니다.
위치는 허용 여부만 남기고 좌표는 전송하지 않습니다.

환경변수가 하나라도 비면 분석은 초기화되지 않습니다. 로컬 개발과 테스트가 통계를
오염시키지 않는 것은 이 때문입니다. 광고차단기에 막히거나 쿠키가 꺼진 브라우저에서도
이벤트는 버려지기만 하고 화면은 그대로 동작합니다.

수집 항목과 거부 방법은 `/privacy` 페이지에 적어 두었고 푸터에서 연결됩니다.
